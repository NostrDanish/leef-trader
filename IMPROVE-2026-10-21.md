## Quick wins (code/config)

### Unauthenticated quota-spend endpoints — concrete design

`api/jev.ts`: validation is good (64 KB body cap, ≤64 typed questions, 30 s upstream
timeout, no logging of state) but every accepted request is a **billed upstream inference**
and there is no caller identity, rate limit, or cache. `api/token-risk.ts` is cheaper
(1–4 tokens, known-token short-circuit, 6 h cache) but the cache is an in-memory `Map` —
per serverless instance, cold on every scale-to-zero, so the quota shield is weak.

Layered fix, cheapest first:

1. **(S) Platform rate limiting.** Vercel WAF/Firewall rate-limit rule on `/api/jev` and
   `/api/token-risk` (e.g. 10 req/min per IP) — dashboard-only, no code.
2. **(S) Global daily circuit breaker.** A Vercel KV/Upstash counter:
   `INCR jev:daily:<date>`; over `JEV_DAILY_CAP` (say 500) return `{available:false}`.
   The client already degrades gracefully (`askJev` → null = advisory unavailable), so a
   tripped breaker never breaks the app — it just stops the bleeding. This is the single
   highest-value change: it converts unbounded quota spend into a bounded one.
3. **(S) Shared cache.** Move the token-risk `Map` to the same KV (key `tokenId`, 6 h TTL)
   so the cache actually works across instances; add a short (60 s) KV cache to `/api/jev`
   keyed by `sha256(state+questions)` to absorb bot-loop retries.
4. **(M) Owner-auth middleware.** This is a single-operator desk: `aiControl: "control"` is
   the owner's feature, so `/api/jev` can require a signed Nostr **NIP-98** event
   (kind 27235, `u` + `method` tags, `created_at` within ±60 s) whose pubkey equals an
   env-pinned `OWNER_NOSTR_PUBKEY`. Verification is ~30 lines with `nostr-tools` (already a
   dep). Keep `/api/token-risk` public-but-cached (it powers a UI warning for all visitors).
   Leef-signer's worker already has a `publicAuth` seam for the same pattern — fix it there
   (see its report) and reuse the approach here for consistency.

### CSP report-only → enforce

`vercel.json` ships an enforcing header with only `frame-ancestors` and a full
`default-src 'none'` policy under `Content-Security-Policy-Report-Only` — but with **no
report destination** the report-only header is inert. Path:

1. Add `report-uri`/`report-to` pointing at a tiny collector (the existing Cloudflare
   worker can accept `POST /api/csp-report`; body ≤ 8 KB, no auth needed — CSP reports are
   self-rate-limited by browsers).
2. Soak 1–2 weeks, triage violations (watch: `style-src 'unsafe-inline'` — try dropping it
   with Tailwind v4's compiled CSS; `connect-src` blob:/wss: entries are expected).
3. Promote the policy to the enforcing `Content-Security-Policy` header (merge with
   `frame-ancestors`). There is already a `security/csp-allowlist` branch — fold this in
   before the branch prune deletes the work.

### Jev execution seam — rollout gaps

What's already right: off/suggest/control tri-state with confirm-gated `control`
(`terminal.ts`), proposal invalidated on mode change, confidence floor 0.75 on the weakest
judgment, risk-noul vetoes (`execOk < 0.5` kills any non-hold; stress vetoes entries only),
pure/testable `ai-executor.ts` with tests, unchanged execution gauntlet downstream,
fail-closed client (`askJev` → null).

Missing for safe rollout:

1. **Automatic tripwire (S–M).** `aiControl` persists in localStorage — if Jev degrades or
   the desk is left unattended in `control`, nothing reverts it. Add: N consecutive Jev
   fetch failures **or** M consecutive executed proposals closing at a loss **or** K
   consecutive gate rejections ⇒ auto-set `aiControl: "off"` (journal + toast). One-way,
   requires fresh human confirm to re-enable.
2. **Execution audit record (S).** `journal.ts` logs `kind: "ai"` for auto-reviews; ensure
   every AI-*triggered execution* also journals an immutable record: action, params,
   confidence, weakest qid, rationale, and a hash of the raw answers — needed to answer
   "why did the bot do that?" after the fact.
3. **Client-side Jev budget (S).** `ai-analyst.ts` has `aiBudget()` (18/min); the Jev loop
   has no equivalent. Add the same sliding window (e.g. 6/min — the loop is per-cycle) so a
   tight tick cadence can't hammer your own endpoint (compounds with the server-side cap).
4. **Consider session-scoping `control` (S).** Persist only `off`/`suggest`; require
   re-confirm after a full reload. Small friction, large unattended-risk reduction.
