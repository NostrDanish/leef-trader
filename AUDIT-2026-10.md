# Security Audit — NostrDanish/leef-trader — 2026-10-20

## Summary
Public TypeScript/React (Vite) browser trading terminal + bot for the LEEF ecosystem on WAX (Alcor CLMM, Defibox, TacoSwap), deployed as a static SPA on Vercel with one serverless function (`api/token-risk.ts`). Signing is fully client-side via Wharfkit wallets (WCW/Anchor) or an optional in-memory session key (WIF/PVT_K1) that is never persisted and is zeroized on teardown (`security/zeroize-session-key` merged). Every transaction passes a policy firewall (allowlisted contracts/actions/tokens, receiver pinned) and arb enforces a profit floor on-chain. No secrets, keys, or tokens were found anywhere in the repo. Findings: 0 CRITICAL / 0 HIGH / 2 MEDIUM / 3 LOW.

## Secrets Check
Scanned/reviewed: `.env.example`, `.gitignore`, `vercel.json`, `.mcp.json`, `.gitlab-ci.yml`, `.github/workflows/*`, `tools/seed-snapshot.mjs`, `src/lib/wallet/secret.ts`, `src/lib/wallet/session.ts`, `src/lib/leef/ai-analyst.ts`, plus repo-wide code searches for `nsec1`, `PVT_K1`, WIF `5J`, `privateKey`, `sk-`. **No private keys, API keys, tokens, or passwords found.** `.gitignore` covers `.env*`; `.env.example` contains placeholders only. Note: GitHub code search returned `incomplete_results` for this repo, so manual file review was the primary check; automated secret scanning (GHAS) is not enabled on the repo — enable it + push protection.

## Dependency Notes
Manifest + committed `package-lock.json` (~298 KB) reviewed; modern stack (@wharfkit/*, React 18, Vite 6, vitest). No git-URL or wildcard dependencies observed. No abandoned critical deps identified. Keep lockfile committed and run `npm audit` in CI.

## Code Red-Flag Review
- No eval/exec of remote input; no remote code loading (CSP connect-src allowlist, third-party CORS proxy restricted to GET reads; signed transactions never proxied).
- Session-key path (`secret.ts`/`session.ts`): in-memory only, zeroized, not transmitted — matches README security model.
- AI analyst client (`ai-analyst.ts`): off the trade path, client-side rate budget, gateway forces `trade_authorization:false`. Good isolation.
- `api/token-risk.ts` is the only server surface: fails closed when key missing, no user input executed, capped token count.

## Recommended Actions
1. Promote report-only CSP to enforced (LT-1).
2. Rate-limit/auth the `token-risk` serverless function (LT-2).
3. Enable GHAS secret scanning + push protection.
4. Prune stale branches (LT-4); pin MCP dev tools (LT-3).
5. Add root `SECURITY.md` (LT-5).
6. Keep `TYPESAFE_API_KEY` in Vercel env only — never in `VITE_*` vars (current design is correct).
